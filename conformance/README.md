# MMP v2.0 Conformance Test Vectors

The machine-readable vectors this specification names as the **normative
contract**. A conforming implementation MUST reproduce every expectation
exactly.

| File | Sections | Covers |
|---|---|---|
| `v2/application-v2.json` | Record model | Absent/present application commitments and exact opaque-byte integrity |
| `v2/record-signature-v2.json` | Record model, security | `cmb-` Merkle cognition address, `mmp-sig-v2.0`, assertion identity, signed author nodeId and application commitment |
| `v2/handshake-v2.json` | Identity, connection, security | Transcript bytes, Ed25519 proofs, X25519 key confirmation, HKDF finished and traffic keys |
| `v2/e2e-v2.json` | Security | IETF ChaCha20-Poly1305 envelopes, directional counter nonces and transcript-bound AAD |
| `svaf-baseline.json` | §9.2, §9.2.1 | Reference-baseline admission math on fixed field vectors: nearest-anchor redundancy basis (both witness directions), aligned/guarded thresholds, the evaluation-time flip window, cold-start bootstrap |
| `tether-v1.json` | §15.8 | Lineage-tether drift checks (faithful / severed / unverifiable / α-weighted), `mmp-tether-v1` attestation payload bytes + signature, kernel comparability |

Cryptographic vectors use **fixed TEST keys and nonces** included in the files.
Never use them as an identity or session key.

The v2 vectors are generated by the implementation-neutral constructor in this
repository and independently re-derived by `scripts/verify-vectors.mjs`:

```bash
npm ci
npm test
```

SYM, Swift and xmesh-core boundary tests consume these published files; no
reference implementation defines private alternative bytes. The retired
`cmb1-` and `mmp-sig-v1` vectors were removed because they describe a pre-v2
flat record and are not MMP v2.0 conformance data.

The SVAF vectors carry raw category vectors and no text: they test the baseline
math, not an encoder. Live admission remains receiver-autonomous; thresholds
are comparable only within a pinned encoder/kernel.
